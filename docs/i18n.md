# 다국어(i18n) 관리 가이드

## 구조

```
src/i18n/
  index.ts          런타임 — 로케일 레지스트리, useLocaleStore(persist), useT()/t(), formatDate, MOD_KEY
  types.ts          en 에서 파생한 타입 — Messages(모양), MessageKey(점 경로 유니온), 자리표시자 검사
  Rich.tsx          <b>/<strong>/<kbd>/<code> 태그만 React 요소로 바꾸는 렌더러
  locales/
    en.ts           기준(source of truth) 로케일
    ko.ts           한국어 — `const ko: Messages` 로 en 과 같은 모양을 강제
src/components/LanguageSelect.tsx   지구본 버튼 + 언어 메뉴 (compact = 아이콘만)
```

외부 라이브러리 없이 TypeScript 타입만으로 다음을 컴파일 타임에 보장한다.

| 실수 | 결과 |
|---|---|
| ko 에 키 누락 / en 에 없는 키 추가 | `ko.ts` 타입 에러 |
| 존재하지 않는 키로 `t('...')` 호출 | 호출부 타입 에러 |
| `{title}` 같은 자리표시자 인자 누락·오타 | 호출부 타입 에러 |
| 런타임에 번역이 비어 있음(동적 키 등) | ko → en → 키 문자열 순으로 폴백 |

언어는 첫 방문 시 `navigator.languages` 로 감지하고, 사용자가 바꾸면 localStorage(`whiteboard.locale.v1`)에 저장한다.
`<html lang>` 과 문서 제목은 `bindDocumentLocale()` 이 자동으로 맞춘다.

## 사용법

```tsx
import { useT, t, useFormatDate, MOD_KEY } from '@/i18n'
import { Rich } from '@/i18n/Rich'

// 컴포넌트 렌더 — 언어 변경 시 다시 그려진다
const t = useT()
<button title={t('toolbar.undo', { mod: MOD_KEY })}>{t('common.undo')}</button>
<Rich text={t('tokens.issued', { name })} />   // 값에 <strong> 태그가 있는 메시지

// 컴포넌트 밖(스토어, 토스트, 기본 제목 생성 등) — 호출 시점 언어로 문자열이 확정된다
import { t } from '@/i18n'
toast.show(t('boards.deleteFailed'), { tone: 'danger' })
```

- 날짜는 `toLocaleDateString('en-US')` 를 직접 쓰지 말고 `useFormatDate()` / `formatDate(value, locale)` 를 쓴다.
- 오류 상태를 state 에 담을 땐 번역된 문자열보다 **키**를 담아 두고 렌더 시 `t(key)` 하는 편이 언어 전환에 강하다 (`OAuthCallbackPage` 참고).
- 동적 키(`share.roles.${role}`)는 템플릿 리터럴 타입으로 검사된다. 서버 값처럼 키가 보장되지 않으면 `isKnownCategory` (Sidebar) 처럼 가드 후 쓴다.

## 규칙

1. **기준 언어는 영어(`en.ts`)**. 새 UI 문자열은 항상 `en.ts` 에 먼저 추가하고, 같은 PR 에서 `ko.ts` 도 채운다(타입 에러가 나므로 빠뜨릴 수 없다).
2. **키 = `네임스페이스.의미`**. 최상위는 화면/기능 단위(`auth`, `boards`, `editor`, `toolbar`, `share`, `tour` …). 문구가 아니라 역할로 이름 짓는다 — `deleteFailed` (O), `failedToDeleteTheBoard` (X).
3. **공통 문구만 `common` 으로**. 같은 단어라도 맥락이 다르면(버튼 "Revoke" vs 확인 "Confirm revoke") 키를 나눈다. 언어마다 다르게 번역될 수 있기 때문.
4. **문장을 조각내서 이어 붙이지 않는다**. 어순이 언어마다 다르므로 `{param}` 자리표시자를 쓴다 — `'Updated {date}'` / `'{date} 수정'`.
5. **서식은 메시지 안 태그로**. `<b>`, `<strong>`, `<kbd>`, `<code>` 만 허용되며 `<Rich>` 로 렌더한다. 링크처럼 상호작용이 필요한 부분은 키를 나눈다 (`auth.login.noAccount` + `auth.login.signupLink`).
6. **번역하지 않는 것**: 사용자 입력 데이터(보드 제목·사용자 이름·노드 라벨), 제품/기술 이름(카탈로그의 PostgreSQL 등)과 카탈로그 카테고리명(ko 에서도 영어 값 유지), 브랜드명. 단, 앱이 생성하는 기본값(`New board`, `Guest`)은 생성 시점의 언어로 만든다.
7. 코드 주석·커밋 메시지는 기존대로 한국어.

## 새 언어 추가

1. `src/i18n/locales/ja.ts` 를 만들고 `const ja: Messages = { ... }` 로 작성 (ko.ts 복사 후 번역).
2. `src/i18n/index.ts` 의 `LOCALES` 에 `ja: { label: '日本語', messages: ja }` 한 줄 추가. `label` 은 그 언어 자신의 이름으로.
3. `npm run typecheck` 가 통과하면 끝. 언어 선택 UI 와 브라우저 언어 감지에 자동 반영된다.

## 운영 제안 (단계별)

**지금 (2개 언어, 문자열 약 190개)** — 현재 구조 그대로. 번역 파일이 TS 라 리뷰가 쉽고, 타입 검사가 사실상 CI 검증 역할을 한다(`npm run build` 가 `tsc -b` 포함).
PR 체크리스트에 "새 UI 문자열은 en/ko 둘 다 추가했는가"만 두면 된다.

**언어가 3개 이상이거나 번역가가 개발자가 아닐 때** —
- 로케일 파일을 `locales/*.json` 으로 바꾸고 `en.json` 에서 타입을 생성하는 방식(현재 `types.ts` 의 `typeof en` 을 그대로 사용 가능, `resolveJsonModule`)으로 옮긴다.
- Crowdin / Lokalise / Tolgee 같은 TMS 를 GitHub 연동해 `en.json` 변경 시 번역 작업이 자동 생성되고, 완료되면 PR 로 들어오게 한다.
- 미번역 키를 en 으로 폴백하는 현재 동작을 유지하면 번역이 늦어도 배포를 막지 않는다. 이때는 `ko.ts` 의 완전성 강제를 `Partial` 로 완화하고, 대신 CI 에서 "누락 키 리포트"만 출력한다.

**번들/기능이 커질 때** —
- 로케일별 동적 `import()` 로 현재 언어만 로드 (지금은 두 언어 합쳐 수 KB 라 불필요).
- 복수형이 필요한 문구가 생기면 `Intl.PluralRules` 기반 `{count, plural, …}` 지원을 추가하거나, 그 시점에 ICU MessageFormat 을 지원하는 `i18next`/`FormatJS` 로 이전한다. 키 구조와 `t(key, params)` 시그니처가 같으므로 이전 비용이 작다.
- 원격 모드에서 사용자 프로필에 선호 언어를 저장해 기기 간에 동기화한다.

**품질 관리 아이디어** —
- 의사 로케일(pseudo-locale, 예: `[!! Ŝĥåŕé ƀöåŕð !!]`)을 개발 모드 전용으로 추가하면 하드코딩된 문자열과 길이 넘침을 한눈에 찾을 수 있다.
- ESLint `react/jsx-no-literals` (또는 `eslint-plugin-i18next`) 로 JSX 안 하드코딩 문자열을 경고.
